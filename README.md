# TKA Rich Presence

Source for **v0.4.0-beta** of the community Discord Rich Presence mod for **The Killing Antidote**. Author: **IkkiTsuki (hikarinovamente)**.

The release displays the current map, Story/Challenge mode, difficulty, health percentage and session time. It supports Brazilian Portuguese and English, map/menu artwork, customization room artwork, vending UI status and a temporary save-trigger status.

Steam Workshop: https://steamcommunity.com/sharedfiles/filedetails/?id=3833552841

## How it works

1. UE4SS loads `TKA_RPC/Scripts/main.lua`. Game data is sampled every five seconds through `ExecuteInGameThread` and written as JSON state records in `UE4SS.log`.
2. `AutoStart.lua` locates the installed mod and invokes `Bridge/AutoStart.ps1` through Windows PowerShell. The command is UTF-16LE/Base64 encoded to quote paths safely.
3. The PowerShell script identifies the matching game executable and starts the bundled helper hidden, passing the game's process ID.
4. `TKA-RPC.exe` contains the Node.js runtime and a small bootstrap. The application's readable JavaScript remains in the adjacent `rpc` directory.
5. The helper tails the UE4SS log and sends activity to the Discord desktop client's local named pipes. It enforces one helper instance per application ID, retries Discord connections and exits when the game process ends.

The mod observes game fields and save callbacks; it does not modify saves, health or difficulty. A save-trigger status means a function was called, not proof that writing the save finished. Customization artwork is tied to the visible customization UI, not room occupancy. Session time includes menus/loading. Brief interactions may be missed between updates.

## Requirements for players

- Windows x64 and the Steam edition of The Killing Antidote.
- Discord desktop with activity sharing enabled.
- Working **UE4SS**, tested with **v3.0.1-1195-g1ceefac8** and the `ue4ss/Mods` layout on Unreal Engine 4.27. Other builds are not guaranteed compatible.
- The complete compiled mod package. **Players do not need a separate Node.js installation.**

UE4SS is not included: [official releases](https://github.com/UE4SS-RE/RE-UE4SS/releases), [installation documentation](https://docs.ue4ss.com/installation-guide.html).

## Install the compiled release

Close the game. Copy the entire packaged `TKA_RPC` directory into:

```text
<Steam library>/steamapps/common/TheKillingAntidote/TheKillingAntidote/Binaries/Win64/ue4ss/Mods/
```

The installed tree must contain:

```text
Mods/TKA_RPC/
  enabled.txt
  Scripts/main.lua
  Scripts/Interactions.lua
  Scripts/AutoStart.lua
  Bridge/AutoStart.ps1
  Bridge/TKA-RPC.exe
  Bridge/rpc/config.json
  Bridge/rpc/*.cjs
```

Open Discord desktop and launch the game normally. The helper starts automatically; allow approximately 20 seconds for activity to appear. Closing the game clears activity and ends the helper. No Windows startup entry or scheduled task is created.

For the Workshop download, copy `TKA_RPC` from `<Steam library>/steamapps/workshop/content/2254890/3833552841/` into `ue4ss/Mods`. Subscribing downloads the files but does not perform that manual installation. Unsubscribing does not remove the folder you copied. After a Workshop update, copy the updated folder again with the game closed.

**GitHub's source archive is not a ready-to-install mod.** Build and package it first, or use the compiled Workshop/Nexus package supplied by the author.

To select a language, edit installed `TKA_RPC/Bridge/rpc/config.json`, set `"language": "en"` or `"language": "pt-BR"`, and restart the game. PT-BR is the default. The public Discord application ID and asset keys in this file are identifiers, not credentials. Keep `logPath` empty for automatic relative discovery.

To uninstall, close the game and remove only `Mods/TKA_RPC`. Leave UE4SS and other mods in place.

## Build from source

Use **Windows x64 and official Node.js v26.13.0 x64** to match the release's build environment. The version is recorded in `.node-version` and `package.json`. Building requires Node; running the packaged mod does not.

```powershell
git clone https://github.com/ikkitsukii/TKA-Rich-Presence.git
cd TKA-Rich-Presence
node --version
node --test tests/rpc.test.cjs tests/autostart.test.cjs
node scripts/build-executable.cjs
node scripts/package-autostart.cjs
```

No `npm install` or package download is required: the runtime and build scripts use Node's built-in modules only. `npm test`, `npm run build` and `npm run package` are equivalent shortcuts.

Build outputs:

- `.tools/sea-build/entry.cjs`: exact small bootstrap generated by the build script.
- `.tools/sea-build/sea.json`: Node SEA settings.
- `TKA-RPC.exe`: generated standalone runtime/bootstrap executable.
- `dist/TKA-RPC-0.4.0-beta-autostart/`: complete installable directory and SHA-256 manifest.

The build uses Node's `--build-sea`, disables snapshots/code cache and does not apply a custom packer, encryption or JavaScript obfuscator. It copies the Node executable and embeds the bootstrap; the application modules remain plain source files. The executable is not Authenticode-signed by the mod author. See [BUILD.md](docs/BUILD.md) for the exact bootstrap, verification and reproducibility limits.

The packaging script intentionally refuses to overwrite an existing release directory. Use a fresh checkout/output location for another build. It does not fetch or include UE4SS, game files, source images, editing tools, credentials or play logs.

## Review and tests

```powershell
node scripts/audit-source.cjs
node --test tests/rpc.test.cjs tests/autostart.test.cjs
```

Optional Lua checks, using a compatible Lua 5.3/5.4 interpreter:

```text
lua tests/autostart_spec.lua
lua tests/save_interactions_spec.lua
```

These checks also run with the optional Fengari Node CLI 0.1.0 used during development. That interpreter is a development test tool, not a runtime/build dependency or release component. No game installation is needed for the automated tests.

The lifecycle test creates a temporary fixture and child processes, then cleans up its own fixture. It may attempt a handshake with a locally running Discord client using a synthetic application ID; it does not publish a game activity.
